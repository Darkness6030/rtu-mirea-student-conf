# СтудКонф — сервис организации студенческих конференций

Индивидуальный проект по дисциплине «Технологии разработки приложений на базе
фреймворков». ПР1 → ПР2 → ПР3 → ПР5 реализованы последовательно в одном Git-репозитории.
Предметная область: научные конференции студентов, их секции, участники и доклады.

## Быстрый запуск

Нужен Python 3.11 или новее. Проверено на Python 3.12.10, Django 5.2.17.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py check
python manage.py runserver
```

Открыть <http://127.0.0.1:8000/>. На Windows активация: `.venv\Scripts\activate`.
Bootstrap 5.3.8 и собственные стили находятся в `static/`, интернет после установки
Python-зависимостей не требуется. База данных и миграции для ПР5 не нужны.

## Возможности и ограничения этапа ПР5

В браузере доступны главная страница со сводкой, списки и карточки всех четырёх
сущностей, ссылки между ними, статус подачи, сроки приёма и заполненность секций.
Неизвестный адрес или идентификатор возвращает HTTP 404. Повреждённое хранилище
возвращает 503 с понятным сообщением, сохраняя исходный файл.

Создание конференций, студентов, секций, подача и отмена докладов выполняются в
**консоли**. В соответствии с методичкой ПР5 веб-интерфейс только отображает данные:
ORM, база данных, Django Forms, регистрация, авторизация и редактирование через
браузер относятся к следующим этапам. Django-шаблоны также пока не используются:
view-функции возвращают `HttpResponse`, HTML собирается общими функциями `homepage/ui.py`.
Значения из JSON экранируются через `format_html` и `format_html_join`.

## Предметная модель

| Сущность | Данные | Связи и поведение |
| --- | --- | --- |
| Conference | id, название, дата, срок подачи, место | `is_open()` учитывает последний день приёма |
| Student | id, ФИО, группа | Участник конференции, не аккаунт Django |
| Section | id, название, лимит докладов | Ссылка на Conference; `has_free_slot()` |
| Talk | id, тема, аннотация, статус отмены | Ссылки на Student и Section; `cancel()`, `status` |

Правила: дедлайн не позже даты конференции; лимит положительный; активные доклады
не превышают лимит; одинаковая тема одного студента в одной секции не подаётся
повторно без отмены предыдущего доклада. При сравнении темы регистр не учитывается.
Отмена сохраняет историю и освобождает место. Отменить можно и после дедлайна.
Конференция доклада определяется через секцию, отдельная дублирующая связь не хранится.
Встроенный пример содержит 2 конференции, 3 секции, 3 студентов и 4 доклада (один отменён).
Даты примера фиксированы; после дедлайна статус приёма автоматически изменится.

## Страницы и view-функции

| URL | View | Назначение |
| --- | --- | --- |
| `/` | `homepage.views.index` | Главная и сводка |
| `/conferences/` | `conference_list` | Список конференций |
| `/conferences/<int:conference_id>/` | `conference_detail` | Конференция и её секции |
| `/students/` | `student_list` | Участники |
| `/students/<int:student_id>/` | `student_detail` | Студент и его доклады |
| `/sections/` | `section_list` | Секции по возрастанию лимита |
| `/sections/<int:section_id>/` | `section_detail` | Секция, доступность, доклады |
| `/talks/` | `talk_list` | Все доклады |
| `/talks/<int:talk_id>/` | `talk_detail` | Аннотация, автор, секция, конференция |

Пример: `GET /talks/1/` → `studentconf/urls.py` → `talks/urls.py` →
`talk_detail(request, talk_id=1)` → `storage.load_state()` → поиск объекта →
общие HTML-компоненты → `HttpResponse` с кодом 200. Отсутствующий объект вызывает
`Http404`; `handler404` возвращает собственную страницу с кодом 404.
Маршруты именованы (`talks:detail` и т. п.), ссылки формируются через `reverse()`.
Поддерживаются GET и HEAD; попытка POST к предметной странице возвращает 405.

Для проверки собственной 404 без отладочной страницы:

```sh
DJANGO_DEBUG=0 python manage.py runserver --insecure
```

`--insecure` здесь разрешает раздачу локального CSS только для демонстрации через
сервер разработки. Для обычной разработки достаточно команды из быстрого запуска.
В PowerShell: `$env:DJANGO_DEBUG="0"`, затем `python manage.py runserver --insecure`.

## Консольные этапы и данные

```sh
python -m pr1.main          # ПР1: проверка срока и свободных мест
python -m pr2.main          # ПР2: коллекции и функции
python main.py             # ПР3: те же сценарии на объектах
python main.py --data data/runtime.json
```

Меню: 1 — просмотр; 2 — конференция; 3 — студент; 4 — секция; 5 — подача;
6 — отмена; 7 — поиск по теме; 8 — фильтр по лимиту; 9 — сортировка; 0 — выход.
Каждая успешная изменяющая операция сохраняется автоматически.

Первый запуск читает `data/sample.json`; консоль ПР2 пишет `data/runtime-pr2.json`,
ПР3 — `data/runtime.json`. Веб-слой использует `runtime.json`, если он есть,
иначе — пример. Через `CONFERENCE_DATA_FILE` можно указать другой JSON:

```sh
CONFERENCE_DATA_FILE=/absolute/path/snapshot.json python manage.py runserver
```

Четыре коллекции хранятся одним согласованным снимком. Перед записью проверяются
поля, уникальность ID, связи и лимиты. Затем временный файл атомарно заменяет целевой.
Неверный существующий файл не подменяется примером. Загрузка сначала создаёт конференции
и студентов, затем секции и доклады со ссылками на общие экземпляры объектов.
Веб читает свежий снимок при каждом запросе. JSON предназначен для учебного локального
использования с одним процессом записи; одновременная запись из нескольких консолей
не поддерживается.

## Структура

```text
pr1/                     начальный сценарий
pr2/                     функциональная версия
models/                  классы ПР3 (не Django ORM)
services.py              сценарии и поиск объектов
validation.py            правила и контракт JSON
json_store.py, storage.py сериализация и восстановление связей
console.py, main.py       консольный интерфейс
studentconf/             settings, корневые URL, WSGI, ASGI
homepage/                главная, ошибки, загрузка данных, HTML-компоненты
conferences/, students/  приложения списков и карточек
sections/, talks/        приложения списков и карточек
static/                  локальные CSS и Bootstrap с лицензией
learning/                учебные примеры ООП и декораторов
data/                    исходный пример; локальные runtime-файлы исключены из Git
tests/                   тесты этапов и HTTP
scripts/                 воспроизводимая сборка отчёта из образца
docs/                    неизменённые исходные отчёты и методичка
results/                 отчёт ПР5 и ответы на 52 контрольных вопроса
evidence/                протоколы проверок и снимки интерфейса
```

## Проверки

```sh
python -m pytest -v
python -m flake8 .
python manage.py check
```

58 тестов: ПР1 — 7, ПР2 — 14, ПР3 — 7, веб-слой — 30. Проверяются границы
срока и лимита, отмена и повторная подача, JSON, объектные ссылки, все маршруты,
отсутствующие ID, экранирование HTML, пустые данные, повреждённый JSON,
обновление снимка, HTTP-методы и обход всех внутренних ссылок.
Протоколы `evidence/pr*-tests.txt` отражают состояние соответствующего этапа.
В `evidence/pr5-browser.txt` — проверка браузером, в `evidence/web-*.png` — снимки
настольного и мобильного интерфейса. `evidence/pr1-debug.txt` — реальный сеанс pdb
на отдельной учебной копии с ошибкой границы срока.

## Git и учебные материалы

```sh
git log --oneline --reverse
git show PR3:main.py
git diff PR3..PR5 --stat
```

Коммиты помечены `PR1:`, `PR2:`, `PR3:` и `PR5:`. Перед веб-слоем создана отдельная
контрольная точка с планом (`evidence/pr5-plan.md`). ПР4 — контрольная работа,
отдельного этапа изменения проекта нет. Удалённый репозиторий не настроен;
вся история находится в `.git` этой папки.

Исходные отчёты использованы как образцы последовательности разработки;
предметная область заново реализована для конференций. Отчёт ПР5 оформлен по образцу
с ФИО Кирьянов Константин Николаевич, группа ЭФБО-01-24. Темы раздела 04
«Создание проекта», «Пути и view-функции», «Вёрстка для бэкендера» отражены в коде.
Выполнение заданий в личном кабинете Яндекс Практикума здесь не подтверждается.
